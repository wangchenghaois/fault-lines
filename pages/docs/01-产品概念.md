# 歧见 · Fault Lines

> **不告诉你答案，告诉你答案为什么分成两半。**

参赛：知乎 S3・湾区共创季 · 赛道 01「社区 × 知识发现」
形态：可运行 Web 原型（本地推理，零 API Key）
一句话：把一个知乎问题下的 N 个高赞回答，变成一张**观点断层图**——标出哪些是真分歧、哪些只是说法不同、哪些根本不可能靠证据解决。

---

## 一、我们要回答的新问题

绝大多数「AI + 知识」产品在回答同一个问题：**怎么更快地拿到答案**。
搜索给你一个答案，大模型给你一个综合答案（顺手把分歧抹平），推荐流给你一个你本来就爱听的答案。

但知乎真正的资产不是答案，是**同一个问题上高质量的相互反对**——有人认真写三千字驳斥另一个也认真写了三千字的人。这是中文互联网上最稀缺的东西。

问题是：**没人读得完。** 一个问题 800 个回答，读者翻到第 20 个就开始只记得「各有道理」。这是信息过载导致的认知退化：他知道存在分歧，但不知道分歧在哪、为什么分歧、哪些分歧根本不值得争。

所以歧见要回答的是另一个问题：

> **这场争论，究竟断在哪里？**

不是「谁对」，而是「他们在哪一点上真的不同、这一点能不能被证据解决、如果我站这边我必须接受什么」。

---

## 二、核心机制：五层处理

输入：一个知乎问题的标题 + 若干条回答正文（粘贴导入 / 示例集）。
输出：一张可交互的断层图。

### 1. 论点萃取（Claim Extraction）
把每条回答拆成原子主张，每条主张打三个标签：

| 标签 | 取值 | 作用 |
|---|---|---|
| 类型 | 事实型 / 价值型 / 预测型 / 义型 / 因果型 | 决定这个论点能不能被证据裁决 |
| 极性 | 支持 / 反对 / 中立 | 用于配对成争点 |
| 隐含前提 | 自由文本 | 分歧的真正来源往往在这里 |

### 2. 争点归并（Issue Clustering）
把指向同一可辩论问题的对立主张聚成一个**争点**。一个回答里通常有 2-4 个主张，一个问题下通常 3-6 个争点——这个数量刚好是人脑能同时持有的上限。

### 3. 断层判定（Fault Classification）— 产品的核心判断
每个争点被判定为三类断层之一：

- **🔵 事实断层**：双方对世界的描述不同，**原则上可被证据解决**。系统给出「需要什么证据才能判定」，并指出谁的论证在证据强度上更硬。
- **🟠 价值断层**：双方对「什么更重要」的排序不同，**不可被证据解决**，这是选择题不是判断题。系统明确标注——停止争论，这是价值观投票。
- **🟣 预测断层**：双方对未来走向的判断不同，**当前不可证伪**，只能等时间。系统给出「什么信号出现就说明哪一方对了」。

> 这一步是整个产品的价值所在：**大部分网络争论的痛苦，来自把价值断层当成事实断层来吵。** 歧见把它指出来。

### 4. 共识提取（Consensus Baseline）
找出各方都默认、但几乎没人明说的前提。这是断层图的「基岩」——先让读者看见「其实你们都同意这 3 件事」，分歧才有意义。

### 5. 信念推演（Belief Inference）— 差异化交互
用户点选自己的立场，系统推出：

- 你已经默认接受了哪些前提（你可能没意识到）
- 基于这些前提，你在**其他争点**上逻辑上应该站哪边（很多时候和用户的直觉相反）
- 你的立场与哪条论据直接冲突——那是你必须付出的代价

这是「重构认知路径」最直接的样子：不是给你更多信息，是让你看见**你的立场会把你带到哪里**。

### 附加两个区域
- **孤证区**：只有一个人主张、无人响应。可能是被忽略的洞见，也可能是噪音——系统不判断，只标注。
- **沉默的多数**：高赞但没有参与任何争点的回答。它们往往提供了最好的背景事实，却不构成争论。

## 三、交互流程（90 秒演示脚本）

| 时间 | 画面 | 说什么 |
|---|---|---|
| 0-10s | 一个问题页，800 个回答的滚动条飞快划过 | 「这个问题有 812 个回答，2.4 万人关注。没人读得完。」 |
| 10-25s | 点击「生成断层图」，本地模型逐条抽取，节点一个个亮起 | 「歧见把每条回答拆成主张，再把这些主张按它们真正在争的东西归类。」 |
| 25-50s | 断层图成型：一条共识基线，四个争点向下生长 | 「它找到 4 个争点。注意颜色——蓝色两个是可以靠证据解决的，橙色那个不能，那是价值选择。」 |
| 50-70s | 点开橙色争点，两侧论据对比，底部一行「真正分歧：对『稳定』的定义不同」 | 「它没有说谁对。它指出了他们在用同一个词说两件事。」 |
| 70-90s | 点「我站这边」，其他争点被高亮重新着色 | 「你选了这边，那你在第二个争点上其实应该站那边——这就是你的立场把你带到的位置。」 |

## 四、与赛题的对齐

| 赛题原文关键词 | 歧见的对应 |
|---|---|
| 「依托知乎沉淀的海量真实问答与多元观点」 | 输入就是同一问题下的多元回答，产品的全部价值来自「观点多且相互反对」这一社区特性 |
| 「用 AI 重构认知路径」 | 不是压缩信息，是重排认知顺序：先看见共识 → 再分清断层类型 → 再推演自己的立场代价 |
| 「帮助用户在纷繁信息中理解观点、梳理逻辑、发掘有效知识」 | 理解观点＝断层图；梳理逻辑＝论点萃取与前提提取；发掘有效知识＝孤证区与沉默的多数 |
| 「观点对照类 AI 应用原型」 | 直接命中 |

**为什么这个作品只有知乎能做**：它需要同一个问题上存在多条高质量、长篇、相互针对性反驳的回答。这是知乎的社区结构决定的，换任何一个内容平台都拿不到这个输入。

## 五、竞品与差异

| 类型 | 代表 | 它的做法 | 歧见的不同 |
|---|---|---|---|
| AI 总结类 | 各类「一键总结长文/多文档」 | 把多份内容**合成一个**答案 | 反向操作：把一个答案**拆成多份**对立主张，保留冲突不抹平 |
| 观点聚合 | 舆情分析 / 立场检测 | 输出「正面 62% / 负面 38%」 | 不问比例，问**分歧的性质**：这条裂纹是能被证据填上的，还是填不上的 |
| 辩论辅助 | 裁判型 AI | 判定谁赢了 | 拒绝判定胜负，只标注「这是判断题还是选择题」 |
| 知识图谱 | 通用 KG | 实体—关系—实体 | 歧见的图是**论辩结构图**（主张—前提—反驳），不是事实图谱 |

核心差异一句话：**别人在做「把复杂变简单」，歧见在做「把混乱变清晰」——这两件事不一样。**

## 六、技术架构与约束

```
导入层   粘贴回答文本 / 内置示例集 / （升级路径）知乎开放接口
   ↓
抽取层   LLM 适配器（默认 Ollama 本地 qwen3.5，OpenAI 兼容协议，可切云端 Key）
         ↳ 规则兜底引擎（无模型时仍可出图，保证演示永不空屏）
   ↓
结构层   论点 → 争点归并 → 断层判定 → 共识提取 → 信念推演图
   ↓
呈现层   SVG 断层图 + 争点详情 + 立场推演（零构建，浏览器直接跑）
```

**三条硬约束（也是设计选择）**：

1. **本地推理优先**：默认走 `127.0.0.1:11434`，社区内容不出本机。这既是隐私立场，也让评委不用配 Key 就能跑。
2. **不爬不存**：不做抓取，内容由用户导入。避合规风险，同时把「数据从哪来」变成用户自己的选择。
3. **永不空屏**：LLM 不可用时自动降级到规则引擎，图照样出来（精度下降，结构仍在）。黑客松现场最怕的就是 demo 时模型挂了。

## 七、一周落地范围

**做**：导入与示例集、五层处理、断层图、争点详情、信念推演、本地服务器、单文件离线版、演示视频。

**不做（明确写进 README 的限制）**：
- 不做真实知乎 API 对接（无 Key，接口未开放申请）——只预留 adapter 接口
- 不做多人协作、账号体系、持久化数据库
- 不做跨问题/跨语言检索（赛道 01 的另一个方向，本作品不覆盖）
- 规则兜底引擎的准确率明显低于 LLM 路径，README 中如实标注
