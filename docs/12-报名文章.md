# 报名文章（可直接发）

> 用法：第五节是知乎专栏正文，直接全选复制；第三节短版用于小红书/朋友圈/表单简介。
> 带 ⬜ 的地方要你填（链接、话题名）。第四节的配图位置按顺序插进正文即可。

## 一、设计思路（先看这三十秒，再决定要不要按我写的发）

报名文章不是项目说明书。评委和路人读它的时候，手里没有任何上下文，他们只想知道三件事，顺序不能乱：

1. **这跟我有什么关系**——所以开头必须是一个他自己经历过的场景，不能是"随着信息爆炸"。
2. **你看见了一个别人没说的东西**——所以要有一个可以被一句话复述的判断（本文是"价值判断被包装成事实判断"）。
3. **你做出了什么，能点吗**——所以 Demo 链接要出现两次（中段一次，结尾一次），而不是埋在最后一行。

我刻意压掉了三样东西：技术栈清单、架构图、"本产品具有以下六大功能"。它们在路演 PPT 里有位置，在文章里只会让人退出。

反过来说，文章里保留了一段"我做不到什么"。这看起来是自曝其短，实际上是这类比赛里最能建立信任的部分——评委见过太多"全栈 + 全模态 + 全场景"的空话，一段具体的边界反而说明你真的做过。

## 二、标题（选一个，我推荐第 2 个）

1. 我给一场争论做了个地质剖面
2. **大部分网络争论的痛苦，来自把价值判断当成事实判断来吵**
3. 不告诉你答案，告诉你答案为什么分成两半
4. 读了八百条回答，我还是不知道他们在吵什么——所以我写了个工具

第 1 个有画面但抽象；第 2 个直接给判断，最容易被转发，也最容易被评委记住；第 3 个是产品标语，适合做副标题；第 4 个是场景，适合小红书。

知乎专栏标题建议：**第 2 个 + 换行副标题「——知乎 S3 湾区共创季参赛作品「歧见」」**。

## 三、短版（约 430 字，用于小红书 / 朋友圈 / 报名表单「作品简介」）

一个高赞问题下有八百条回答。我读完三个小时，关掉页面，脑子里只剩一句：好像两边都有道理。

真正难的不是信息太少，是**争论的类型被混在一起**。有人说"不结婚主要是因为买不起房"，这是事实，能查；有人说"不该催婚，这是个人自由"，这是价值，永远查不出结果；有人说"房价降一半结婚率就会回升"，这是预测，只能等。人在吵架时最常犯的错，是把第二种当成第一种来吵——把自己的价值偏好，包装成能用数据反驳的事实主张。

所以我做的不是"把回答总结一下"，是给这场争论画一张**地质剖面**：每条回答拆成独立主张、标出它是事实/价值/预测/因果/定义；对立的主张配成 2–4 个争点；判定每个争点是哪种断层，以及什么证据能让它结束；再找出所有回答都同意的事，当成这场讨论的地基。

最后一步是我觉得最有意思的：你选一边，它会推出你在**别的争点上逻辑上该站哪边**，并且列出这么站要付的代价。比如你认定"经济压力是不婚的主因"，那你就得承认"结婚成本降一半，结婚率会回升"——可日本的经验是反例。这个反例，就是你选这套立场要付的代价。

前四层让你看清别人，第五层让你看清自己。

## 四、知乎专栏正文（约 3000 字，直接复制）

一个高赞问题下面有八百条回答。

我从第一条读到第四百条，读到眼睛发酸，关掉页面，脑子里剩下的话只有一句：**好像两边都有道理。**

这句话很讨厌。它听起来像是读懂了，其实是什么都没读懂。我说不出他们到底在哪一层上不同，说不出哪一条是可以被数据解决的，哪一条是谁也说服不了谁的。我只知道我很累。

后来我想明白了：**我累不是因为信息太多，是因为这些信息被端上来的时候，类型是混着的。**

### 一、同一场吵架里，混着四种完全不同的东西

拿"年轻人为什么不愿意结婚"这个话题举例。你随手能捡到这样的句子：

- 「不结婚主要是因为买不起房。」——这是**事实**判断。能查，能验，能被数据推翻。
- 「现在的人不再把婚姻当成必选项了。」——这也是**事实**判断，虽然更软，但同样可以被调查数据检验。
- 「不该催婚，这是个人自由。」——这是**价值**判断。它永远查不出结果，因为它不是关于世界是什么样，而是关于世界应该什么样。
- 「如果房价降一半，结婚率就会回升。」——这是**预测**。今天谁也证明不了，只能等时间。

这四句话在同一个评论区里，用同样的语气，排着队出现。于是发生了一件很自然的事：**人们拿对付事实的办法，去对付价值。**

你搬出统计年鉴，对方回一句"数据可以造假"；你举出日本的例子，对方说"国情不同"。你觉得他不讲道理，他觉得你冷血。两个人吵了三百楼，谁也没赢，因为**这场架从一开始就没有共同的裁判**。

我后来越来越觉得，网上大部分争论的痛苦，不是来自"有人跟我意见不同"，而是来自**把自己的价值偏好，包装成了一个可以用数据反驳的事实主张**。包装一旦完成，被反驳就等于被否定，于是只能加码，只能升级，只能互相举报。

### 二、所以我没有做"总结回答"的工具

总结是容易的，也已经被做完了。你让任何一个模型去读八百条回答，它都能给你一段通顺的"综上所述"。但那段话解决不了我上面的问题——它把混在一起的东西**更彻底地搅匀了**。

我想做的是相反的事：**把它切开，按类型分层，让你看见缝在哪里。**

「歧见」的做法是五步：

1. **拆**。把每条回答拆成一条条独立主张，每条标上是事实、价值、预测、因果还是定义，以及它背后依赖了哪些前提。
2. **配**。把互相对立的主张配成 2–4 个争点。一个争点必须是"两边真的顶上了"，不是"提到了同一个词"。
3. **判**。判定这个争点是哪种断层，并且写清楚**什么证据能让它结束**——事实断层等数据，预测断层等时间，价值断层等投票。
4. **找地基**。把所有人都同意的事单独拎出来。争论里最容易被忽略的，是双方共享的那部分前提；没有它，你不知道这场架其实建在什么上面。
5. **推**。你选一边，它推演你在别的争点上"逻辑上该站哪边"。

第五步是我最想让人试的一步，也是我花时间最多的一步。

### 三、第五层：你选的不只是一个立场，是一整套前提

假设你在"不结婚的主因"这个争点上选了"经济压力"。这不是一个孤立的判断。它背后默认了三件事：经济变量是决定性的、人是理性的、制度能改变行为。

于是「歧见」会告诉你：**按照这套前提，你在另外三个争点上，逻辑上只能站这边**——

- 关于"结婚成本降一半会不会回升"：你得说会。
- 关于"该不该改革婚姻与育儿制度"：你得说该。
- 关于"把不婚归因于经济压力是不是偷懒"：你得说不是。

然后它做了一件更不客气的事：**把你这么站要付的代价，摆在你面前。**

比如日本。经济长期低迷，结婚率确实掉下去了，但观念的变化并没有随着经济波动回弹——这恰恰说明"观念"是一个独立变量，不是经济压力的副产品。你选了"经济决定论"，就得想办法安放这条反例。安放不了，那这套立场就是有裂缝的。

我做这一步的时候一直在想一件事：**大多数"观点对立"，其实不是两个人在同一个问题上答案不同，而是他们在不同的问题上，各自答得很自洽。**

### 四、一次具体的走法

我说得太抽象了，不如走一遍。切到「婚育」那一集（问题：为什么现在的年轻人越来越不愿意结婚生子），左边是一张竖着的剖面图，几条水平岩层，每条岩层上戳着几个小方块——一个方块是一个争点，颜色告诉你它是哪种断层：蓝的事实、橙的价值、紫的预测。

我先点蓝色那条：**「不结婚的主因是经济压力，还是观念变化？」** 左边三张卡，右边三张卡，正面对上。

裂缝下方写着判定：

> 双方都在用「主因」这个词，但一方指的是约束条件（能不能），一方指的是意愿（想不想）。这是定义分歧伪装成了事实分歧——所以两边都能拿出数据，且都不算错。

再往下是「什么能让它结束」：

> 需要的数据：控制收入水平后，比较同城市、收入分位但观念不同的群体的结婚率差异。若差异主要由观念解释，则「观念变化」一方胜；若主要由收入解释，则「经济压力」一方胜。

我看到这句的时候愣了一下。它没有回答"谁对"，但它回答了一个更有用的问题：**这场架怎么才算吵完。**

然后我点橙色那条：**「应该改革婚姻与育儿制度，还是不该干预个人选择？」**

同样裂成两边，但裂缝下的判断换了一套语气：

> 这不是事实分歧。一方认为低生育率是需要解决的公共问题，另一方认为它根本不是一个问题。这个分歧无法用数据解决——它取决于你把「社会延续」排在「个人自由」之前还是之后。

> 不可由证据解决。这是价值排序的投票，不是判断题。

两条断层摆在同一张图上，颜色不同、处理方式不同。**这就是我想要的整个产品的那一瞬间。**

最后我回到第一条，点了「站 经济压力」。

下方展开：

> 你的立场要求你在「如果结婚成本下降一半，结婚率会回升吗？」上站「会回升」，代价是你要么接受「观念变化是主因：日本经济停滞三十年，结婚率下降斜率比经济下滑更陡」这条相反论据，要么放弃自己的前提。

接着是三条投影和两条代价。投影说我在另外两个争点上只能站「制度改革」和「成本就是硬约束」；代价里两条都指向同一件事：日本的例子。

那一刻很奇怪：**我没有被人说服，但我看见了自己这套想法长什么样。** 它不是一个孤立的态度，是一套有形状的东西——有支撑点，也有薄弱处，而薄弱处恰好能被一句话指出来。

我认为这就够了。工具不该替你决定，工具该让你看见你已经在哪儿。

### 五、三个我坚持没改的设计决定

**断层颜色不能折叠。** 有人建议我把"事实/价值/预测"合成一个"分歧度"指标，红黄绿三色，一眼看懂。我试过，然后删了。因为一旦折叠，"这是可以查清楚的"和"这是永远查不清的"就变成了同一种东西——而这正是我想让人看见的区别。宁可多一种颜色，也不合并。

**孤证要单独成区。** 常规做法是把所有主张按支持度排序，只有一个人说的自然沉底。但"只有一个人这么说"和"这句话没道理"是两件事。我把孤证单独放在一个区里，因为它们往往是这个领域最值得被重新论证的地方。

**沉默的多数要显式标出。** 有些回答写得很好、很长、很真诚，但它在任何一个争点上都插不上话——它谈的是另一个层面的事。这种回答在常规排序里会被判为"无用"。我把它们单独列出来，因为一个社区里"有人认真说了但没被接住"的部分，恰恰是信息量最大的部分。

### 六、我做不到什么

这段我原本想删，但留着可能更有用。

- **内置的四个示例数据集，是我依据公开讨论重构的，不是知乎原文。** 我没有抓取任何知乎内容。知乎开放平台的接口我按官方文档接了六个（站内搜索、全网搜索、热榜、按主题推荐问题、问题下的回答摘要、额度查询），也写了本机代理绕开浏览器跨域，但**我没有拿到 Access Secret**，所以这些接口只验证到"路径存在、鉴权头格式被接受"这一步，没有用真实凭证跑通过。这一点我写进了文档，也不想在文章里含糊过去。
- **第五层的推演是规则算的，不是模型生成的。** 抽取和归并用了模型（本机跑 4B 的小模型），但"你该站哪边"这一步，是我手写的一张互斥前提表 + 重叠度计算。理由是可追问性：如果让模型生成，每次问它给的答案都不一样，用户没法问"凭什么"；规则至少能被指着说"这张表错了"。这不是能力不足的妥协，是我认为这一层不该由模型来做。
- **公网演示版跑的是规则引擎，不是模型。** 静态托管没有后端，我没有把 API Key 塞进前端。所以你在网页上导入自己的文字，出来的是规则引擎的结果——粗一些，但 0.2 秒就有。想看真模型，得在自己电脑上跑。

### 七、它现在是什么样

一个单文件网页，131 KB，CSS 和 JS 全部内联，双击就能开，不联网也能用。四个内置示例可以直接点（AI 编程工具、读博值不值、婚育、跨境电商独立站）。

代码没有任何构建框架、没有运行时依赖，打包器是我自己写的两百行脚本；测试 551 条断言，其中包含"故意断网、用 file:// 打开、看它会不会白屏"这种检查。

它不完美。**但它跑起来了，而且它说的每句话我都能解释为什么。**

## 六、三条不要写的话

- 不要写"基于大模型的智能分析平台"——评委今天听到这句会自动减分。
- 不要写"准确率 95%""提升效率 300%"——你没有基准，写了就是硬伤。
- 不要写"未来将接入更多平台、打造生态"——这是最容易被追问、也最没有信息量的一句。

## 七、发文后的两小时该做什么（可选）

把文章发到报名要求的地方之后，你自己再读一遍开头三段。如果读完你不知道"这人在抱怨什么"，那就说明开头还没落地——把它换成你昨天真实遇到的一个评论区场景，越具体越好。文章是可以改的，报名链接填一次，但文章会被反复点开。
