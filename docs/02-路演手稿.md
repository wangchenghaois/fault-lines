# 路演手稿 · 歧见 Fault Lines

三个版本：**90 秒电梯版**（初审/线上提交用）、**5 分钟舞台版**（现场答辩主用）、**Q&A 弹药**。

配套演示视频：`build/draft-v2.mp4`（58 秒，1920×1080）。

---

## 一、90 秒电梯版

**【0–10s · 钩子】**
> 你在知乎上问过一个很具体的问题，然后你读了一百多条回答。
> 三个小时过去了。你现在知道"大家意见很不一样"。
> 但你有没有发现——你说不清他们**到底在什么层面上**不一样。

**【10–35s · 洞察】**
> 争论其实有三种断层。
> 第一种，**事实**——能查。谁对谁错，一个数据表就能解决。
> 第二种，**价值**——查不出来。它只能投票。
> 第三种，**预测**——还没发生。只能等时间给答案。
>
> 而绝大多数网络争吵的痛苦，来自**把价值断层当成事实断层来吵**。
> 两个人各自搬证据，谁也说服不了谁——因为那根本不是证据能解决的问题。

**【35–60s · 产品】**
> 歧见做的第一件事，是把一段真实的讨论，拆成一张**断层图**。
> 蓝色是事实，橙色是价值，紫色是预测。你不用读完所有回答，你先看见这道缝在哪里、它是哪种缝。
>
> 第二件事更狠一点。你站到任一边，它会推演出——**你在别的争点上逻辑上必须站哪边**。
> 你选了"经济压力是主因"，那你就得接受"降房价能让结婚率回升"；但你也得接受，那些说"观念变了"的人手里有一条你反驳不了的证据。
> 歧见把那条论据摆在你面前，问你：**这个代价，你认不认。**

**【60–90s · 收尾】**
> 我们不投票，不给结论，不站队。
> 因为争论的价值从来不在谁赢，而在于**看清这条缝在哪里**。
>
> 歧见。不告诉你答案，告诉你答案为什么分成两半。
>
> 全本地运行，零 API Key，你贴上来的东西不出你的电脑。

## 二、5 分钟舞台版

### 0. 开场（30s）——用一个真实场景，不用功能列表

> 上周我搜"读博值不值得"。四千多个回答。
> 我读了两个小时，越读越焦虑，因为每一条都很有道理，而且它们互相矛盾。
> 关掉页面的时候我意识到一件事：**我不是缺信息，我是不知道他们在吵什么。**

（此时切到演示视频第一段，或直接打开本地页面）

### 1. 问题定义（45s）——把"信息过载"重新定义成"类型混淆"

> 搜索引擎假设我们的问题是"信息不够"。所以它给你更多。
> 但知乎上那种问题的困难恰恰相反——信息太多了，而且**不同层次的信息被平铺在一起**。
>
> 一条"房价收入比是 25 倍"（可查的数据）和一条"人不该被婚姻定义"（价值主张），在页面上长得一模一样，都是黑字白底，都有几百个赞。
> 它们在**认识论上**完全不是一个东西。
>
> 这是我认为下一代知识工具真正该解决的事：不是给你答案，是**帮你把问题的结构还原出来**。

### 2. 产品演示（90s）——边操作边讲，不要念功能

打开 `http://127.0.0.1:4188/?ds=marriage`：

1. **先看总图**（15s）
   > 这是"为什么年轻人不愿意结婚"这个问题下的讨论。左边是回答，右边是主张，中间那些带颜色的横带就是争点。
   > 蓝、橙、紫——三种断层。一眼就能看出这个问题的难点不在事实层，橙色那块最厚。

2. **点进一个价值争点**（25s）
   > 这个争点：应该改革婚姻与育儿制度，还是不该干预个人选择？
   > 左边说制度要改，右边说这是个人自由。注意下面这行小字——"永远不会被证据说服"。这不是我的判断，这是这类主张的性质。

3. **点进一个事实争点做对照**（20s）
   > 换一个：不结婚的主因是经济压力还是观念变化？
   > 这个是事实断层，它是**可以被解决的**。区别在这里：一个能查，一个不能。混在一起吵，就是白吵。

4. **站边 → 推演**（30s，全场重点）
   > 现在我做一件这个产品独有的事。我选"经济压力"这边。
   > 它告诉我：我的前提是经济决定论、理性人假设、制度决定论。
   > 然后——如果这些前提成立，那我在另外三个争点上应该站哪边？"降成本会让结婚率回升"、"制度该改革"、"观念变化只是经济压力的表现"。
   > 这三条我确实都同意。**到这里它只是复述我。**
   >
   > 但往下看代价区：它列出了两条**我反驳不了的**论据——日本在就业改善后结婚率没有回升，观念变化有独立的时间线。
   > 它没有说服我，它让我**看见我要为这个立场付什么钱**。

### 3. 为什么别人做不出来（45s）——差异化

> 现在有一堆工具能帮你总结长文。它们的产出是"更短的同一堆东西"。
> 歧见的产出是**结构**：这条缝是事实还是价值，这两边共享什么前提，如果你选这边，你在别处必须站哪边。
>
> 为什么这件事值得做，而不是让大模型直接答？
> 因为大模型最擅长的事恰好是**抹平差异**——它会给你一个"综合来看，两方面都有道理"的答案。而这里需要的正相反：**把差异精确地标定出来**。
>
> 所以歧见把模型用在它真正擅长的位置：抽取和归类。判定和推演是**可解释的规则**——前提标签的互斥表。你能看懂它为什么这么推。

### 4. 工程与边界（40s）——展示诚实

> 三件事值得说：
> 一，**全本地**。默认后端是本机的 Ollama，零 API Key。你把一段私人讨论贴进来分析，不该先上传给某个公司。
> 二，**有兜底**。没装模型也能用，退化成规则引擎，功能完整、精度下降。不是"必须配好环境才能跑"的 demo。
> 三，**数据是示例**。内置四个数据集是我依据公开讨论重构的，不是知乎原文，我在 README 里写清楚了。知乎有反爬，硬爬既不体面也不稳——这个产品的定位是"你有一堆文字，我帮你读懂"，不是"我替你去偷文字"。

### 5. 收尾（30s）

> 我想做的不是又一个总结工具。
> 我想做的是让"我们在吵什么"这件事本身变得可见。
>
> 因为大部分时候，人不是被说服的，人是被**看清**的。
>
> 歧见。不告诉你答案，告诉你答案为什么分成两半。

## 三、Q&A 弹药

**Q：这不就是观点聚类 / 立场分析吗？**
> 聚类解决"哪些说法相似"。歧见解决"这些分歧是什么性质"。前者是分组，后者是**认识论分类**——事实、价值、预测的争议需要完全不同的处理方式。把一个价值争议聚类得很漂亮，并不能让人少吵一句。

**Q：大模型直接问不就行了？**
> 你可以问，它会给一个四平八稳的综述。歧见的差异在于它**拒绝抹平**：它明确标注"这个争点永远不会有答案"，并把这个判断的依据（主张类型）摆出来。而且推演部分是规则算的，你能追。

**Q：凭什么说"你在别处必须站哪边"？人是不一致的。**
> 说得对，人经常不一致——**这正是产品的用处**。歧见不是宣布你"必须"站哪边，是告诉你"你的前提如果成立，逻辑上指向这边"，然后你自己看：要么调整立场，要么承认自己不一致。不一致被看见，比不一致被掩盖好。

**Q：数据从哪来，合规吗？**
> 内置三个是示例，依据公开讨论重构，不是原文引用。真实使用是用户自己粘贴自己关心的内容，全本地处理，不上传。不做抓取。

**Q：商业化？**
> 现在不回答这个。这一周我做的事是证明机制成立。真要商业化，最自然的路径是把它做成阅读器/笔记工具的一个能力，而不是又一个独立 App。

**Q：如果只有一周，最没做完的是什么？**
> 三件：多语言（赛道里有跨语言方向，我没做）、互斥表覆盖面（现在约 20 组标签，人工维护，长尾会漏）、以及真实规模的压力测试（现在是 5–6 条回答的演示集，不是 500 条）。

**Q：为什么叫歧见？**
> "歧见"在中文里是分歧的书面说法，比"分歧"更冷一点、更中性一点。英文 Fault Lines 是地质学的地层断裂——这个产品整套视觉也是地质剖面：一层一层，缝就在那里，不是谁错了。

## 四、现场「喂它一段真话」备选桥段（约 3 分钟）

内置的四个数据集是预分析好的，切起来是瞬时的——评委很容易由此怀疑"这是不是一个写死的 demo"。这一桥段专门用来消解它，**代价是要真等 70–80 秒**。放在问答环节被问到时用，不要塞进主路演。

1. 打开导入弹窗，**用"问题标题（可空）"填问题**，下面粘 3 段立场不同的真实回答（自己的也行，现场观众提供的也行）。
2. 点「开始分析」，把进度条留着别关：它会从 20% 走到 53%，标着「正在拆解第 N/3 条回答」，然后 60% 归并、85% 共识。
3. **等待的时候不要沉默**，讲这三件事：
   - 这些请求全部指向 `127.0.0.1:11434`，没有任何一条出本机（可以当场开浏览器 F12 的 Network 面板给人看）。
   - 每条回答是独立一次调用，所以进度条是按"第几条"走的，不是假的百分比动画。
   - 模型是本机 4.2B、4GB 显存的老显卡，慢是真慢；换 API 会快，但我们选择不上传。
4. 出结果后立刻做一件事：**故意挑一个它判错的争点**，说明断层判定是启发式、会错，然后指出界面上的 `resolveBy`（"需要什么才能判定"）——把"会错"变成可检查。

如果只有 30 秒：直接开 `scripts/uitest.mjs` 的终端输出给人看（`engine=llm`、70.3s、3 条回答 9 条主张），比现场等更省时间。`build/import-demo.mp4` 是这段流程的实况录屏，也可以直接放。

## 五、演示前的检查清单

- [ ] `node server.mjs 4188` 已启动，浏览器打开 `http://127.0.0.1:4188/?ds=marriage`
- [ ] Ollama 在跑（`ollama list` 有 `qwen3.5:4b`），右上角引擎灯是绿的；没跑也能演示（会自动降级，但降级后导入分析走规则引擎，别在评委面前演示导入）
- [ ] **Ollama 会自己退出**——演示前 10 分钟重启一次，并预热一次（跑一遍 `node scripts/repro.mjs`），否则第一条回答会吃满 90 秒超时
- [ ] 浏览器缩放 100%，窗口最大化——断层图是 SVG，缩放会变形
- [ ] 提前点过一次 i1 / i2 / i3，避免现场等首帧
- [ ] `dist/歧见.html` 也在手边——万一现场没网没 Node，双击就能演示（内置数据可离线，导入分析需要 Ollama）
- [ ] 视频文件 `build/draft-v2.mp4` 与 `build/import-demo.mp4` 本地各存一份，别依赖网络
