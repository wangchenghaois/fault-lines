# 歧见 Fault Lines · 产品说明计划书

**赛道**：01 社区 × 知识发现
**一句话**：不告诉你答案，告诉你答案为什么分成两半。

---

## 一、我们要解决的问题

知乎上一个问题下面有几百条回答。你读完三百条，会得到一个模糊的印象：好像两边都有道理。但你不知道**分歧究竟在哪一行**。

更麻烦的是，这些分歧并不属于同一种东西：

- 有的是**事实分歧**——查一下就能解决，只是没人去查。
- 有的是**价值分歧**——永远查不出结果，因为两边对"什么算好"的定义不同。
- 有的是**预测分歧**——只能等时间验证，现在谁嗓门大谁赢。

而人在争论时最常犯的错误，是把第二种当成第一种来吵：把自己的价值偏好，包装成一个可以用数据反驳的事实主张。**大部分网络争论的痛苦，来自这个错位。**

所以我们做的不是"总结这些回答"，而是**给一场争论做地质剖面**：把断层找出来、标出类型、说明它能不能被解决。

---

## 二、核心创作思路

### 2.1 五个层次

| 层 | 做什么 | 产出 |
|---|---|---|
| 1 论点萃取 | 把每条回答拆成一条条独立主张，每条标注类型（事实／价值／预测／因果／定义）与它依赖的前提 | 主张卡 |
| 2 争点归并 | 把互相对立的主张配成"争点"，2–4 个 | 争点列表 |
| 3 断层判定 | 判断每个争点的断层类型，并给出裁决信号（什么证据能让它结束） | 断裂线＋颜色＋理由 |
| 4 共识基线 | 找出所有回答都同意的事——这是这场讨论的地基 | 共识条目 |
| 5 信念推演 | 你选一边之后，推出你在**其他**争点上逻辑上该站哪边，并列出这套立场的代价 | 推演面板 |

### 2.2 为什么第 5 层是重点

前四层是"看清别人"，第五层是"看清自己"。

一个人选了"不婚主要是经济压力"，那他逻辑上必须相信"结婚成本降一半，结婚率会回升"——否则他的因果模型自相矛盾。歧见把这条推论摆出来，同时把**他这套立场无法反驳的那条论据**也摆出来，作为代价。

这是本作品与"AI 总结回答"最本质的区别：**总结让你知道别人说了什么，推演让你知道自己站的位置意味着什么。**

### 2.3 三个反直觉的设计决定

**决定一：断层类型用颜色编码，且不可折叠。**
地质剖面里三种颜色分别代表事实（蓝）、价值（橙）、预测（紫）。它们不能被折叠成"其他"，因为一旦混在一起，用户又会回到"都有道理"的模糊状态。

**决定二：孤证单独成区。**
只有一个人这么说、但说得很认真的观点，在"多数意见"的统计里会消失。歧见把它单独标出来——**它不是错的，它只是还没被反驳过**。这往往是新作者最好的切入点。

**决定三：沉默的多数显式标出。**
"有人问了，没人答"本身是信息。它标记出这个领域的空白位。

## 三、技术实现

### 3.1 架构

```
回答文本 ──┬─→ 主张萃取（LLM 或规则）──→ 争点归并 ──→ 断层判定 ──→ 信念推演（纯规则）
           │                                                              │
           └──────────────────────────────────────────────────────────────┴─→ 断层图（SVG）
```

- **前端**：零框架，原生 JS + SVG。整个应用打包成**单文件 HTML（109.7 KB）**，双击即可离线运行，不需要 `npm install`、不需要后端、不需要网络。
- **推理**：默认走本机 Ollama（`qwen3.5:4b`），也支持 DeepSeek / 通义 / Kimi / 智谱 / OpenAI 等 6 家 OpenAI 兼容端点，填 Key 即用。
- **降级**：模型不可用时自动退回内置规则引擎（约 0.2 秒），功能不残缺，只是抽取粗一些。

### 3.2 一个必须讲清楚的技术选择

**第 1、2 层用模型，第 5 层用规则。**

有人会问：为什么推演不交给模型生成？这样不是更"AI"吗？

因为可追问性。如果推演是模型现场生成的，同一套前提每次运行会得到不同结论，用户没法指着屏幕问"你凭什么说我在这个问题上必须选这边"。而规则推演依赖一张约 20 组的**互斥前提表**（例如"经济决定论"与"观念独立变量"互斥），任何人都能翻开这张表说：这一条我认为不对。

**我们选择了一个可以被指认错误的实现，而不是一个永远正确但无法追问的实现。**

### 3.3 工程指标（实测，非估算）

| 项目 | 数值 |
|---|---|
| 全部自动化断言 | **551 条**（逻辑 385 + 接口 71 + 资源 19 + DOM 50 + 离线 12 + 服务端 14），全绿 |
| 单文件体积 | 109.7 KB |
| 规则引擎分析耗时 | < 0.2 秒 |
| 本机模型分析（3 条回答） | 70–82 秒（GTX 1650） |
| 本机模型分析（4 条回答） | 110–130 秒 |
| 冷启动额外开销 | 一次性约 90 秒（已用预热阶段吸收） |
| 模型不可用时降级耗时 | 43 毫秒，并明确报错而不是静默降级 |

### 3.4 踩过并修掉的真实 bug（说明这版代码被真的跑过）

| 现象 | 根因 | 修法 |
|---|---|---|
| 「AI 分析」从未真正成功，每次都恰好 90 秒超时 | 本地模型 `qwen3.5:4b` 是 reasoning 模型，token 全烧在思维链上，正文返回空串 | 请求带 `reasoning_effort: 'none'`，正文空时明确报错而不是静默降级 |
| 粘贴"空一行"分隔的回答，只识别出 1 条 | 切分正则要求连续 3 个换行，与界面提示不符 | 改为单空行或 `---` 分隔 |
| 后端挂掉时提示"主张数量不足" | 把环境故障甩锅给用户的文字 | 加预热阶段，失败直接说"模型端点无响应，请确认 Ollama 已启动" |
| 进度条从 83% 掉回 60% | 各阶段进度权重重叠 | 重新分配区间 |
| 分析完成但画面冻结 | `alert()` 阻塞渲染线程，浏览器没机会重绘 | 改为页内轻提示 |
| 0 个争点时断层图一片空白，像崩了 | 没处理空结果 | 加空状态说明并给出建议 |

## 四、与知乎社区生态的契合度

赛题原话是「借助知乎社区**内容资产**与**开放接口**」。我们按字面接。

### 4.1 已接入的接口（按官方文档实现）

| 接口 | 用途 |
|---|---|
| `GET /api/v1/user/question_recommendations` | 输入话题关键词 → 拿到相关知乎问题 |
| `GET /api/v1/content/question_answers` | 选一个问题 → 拉该问题下的**真实回答摘要**（一页最多 50 条，带分页游标）→ 直接进断层引擎 |
| `GET /api/v1/content/zhihu_search` | 站内搜索，看某领域的内容与赞同分布 |
| `GET /api/v1/content/hot_list` | 热榜，判断该领域当下是否被关注 |
| `GET /api/v1/quota` | 查当日剩余额度（不消耗额度） |
| `GET /api/v1/user/creator_account_stats` | 创作者本人数据 |

完整链路：**话题 → 推荐问题 → 真实回答 → 断层图**。数据不再是我们编的示例。

### 4.2 接口验证到了哪一步（如实说明）

我们用假凭证打了 6 个端点，全部返回 `20001 Authorization failed`，而故意写错的路径返回 `404 page not found`。这证明：**路径正确、鉴权头格式被服务端接受**，只缺有效凭证。

**没有证明的**：参数名大小写是否正确（知乎先校验鉴权、后校验参数，假凭证走不到参数校验），以及真实数据的字段形状。

原因是我们没有知乎开放平台的 Access Secret。这一点写进了 `docs/08-知乎接口实测.md`，不美化。

### 4.3 为什么浏览器不能直连知乎

知乎接口没有对我们开放 CORS，所以浏览器直接 `fetch` 会被同源策略拦。我们做了一个**只有本机才存在**的代理路由（`/api/zhihu`），Secret 走请求头而不是 URL，并且只允许转发以 `/` 开头的路径（防 SSRF）。

公网静态版没有这个代理——这是有意的：**静态站点不应该持有用户的 Access Secret。**

## 五、场景价值

### 5.1 对读者：从"都有道理"到"知道分歧在哪一行"

一个准备买房的人搜"现在该不该买房"，会看到互相矛盾的回答。歧见告诉他：这个争论里有一个事实断层（租售比数据能不能查到）、一个价值断层（把房子当消费品还是投资品）、一个预测断层（房价三年内走势）。**只有第一种值得他去查资料，第二种需要他自己做选择，第三种谁都给不了答案。**

### 5.2 对创作者：从"追热点"到"看见空白位"

同一个引擎换一个视角：

| 断层图上的位置 | 对创作者意味着 |
|---|---|
| 共识基线 | 入场门槛——不懂这些就别写 |
| 活断层 | 还有读者在等一个说法，适合进攻 |
| 孤证区 | 薄弱但没人认真反驳的角度，适合重新论证 |
| 沉默的多数 | 有人问没人答 = 空白位 |

知乎上有大量"想进某个细分垂类但不知道从哪下手"的新作者。他们最缺的不是流量技巧，而是**这个领域的话已经说到哪儿了**。

### 5.3 对平台：把"观点对立"变成可观测的结构

站内每天产生大量对立讨论。绝大多数平台的处理方式是"折叠""限流""标注争议"。歧见提供另一种可能：**不压制分歧，而是把分歧分类**——事实类引导去查证，价值类引导去投票，预测类引导去等待。这比一刀切的"争议标签"更有建设性。

## 六、后续落地设想

**第一阶段（已完成）**：单文件原型，能跑、能演示、全离线可用。

**第二阶段（接真数据）**：拿到 Access Secret 后，把「话题 → 真实回答 → 断层图」做成主路径；用 `hot_list` 做每日领域扫描，给创作者推"今天有哪个领域的断层在扩大"。

**第三阶段（嵌入社区动线）**：做成知乎回答页的侧栏组件——读到第 N 条回答时，提示"你正在读的这一侧，在另外 2 个争点上也持同样立场"。这是把断层图从"独立工具"变成"阅读时的镜子"。

**第四阶段（创作端）**：把孤证区与沉默的多数做成选题建议，接创作中心的编辑器。**它不告诉你写什么会火，它告诉你哪里还没有人认真写过。**

商业模式上不设付费墙：断层分析属于公共讨论的基础设施，收费会直接损害它的价值。可行的方向是面向创作者的进阶分析（赛道历史对比、跨领域迁移）与面向机构的舆情结构报告。

## 七、诚实边界

这一节不是客套。以下都是真实限制：

1. **没有真实知乎数据**。示例集是依据公开讨论重构的合成数据，成片与界面都标注了「非知乎原文引用」。接口客户端按官方文档实现并验证到鉴权层，但没有 Secret 就无法证明真实返回。
2. **第 5 层推演是规则引擎，不是模型生成**。这是设计选择（见 3.2），但如果评委按"AI 含量"打分，这一层不算 AI 生成。
3. **互斥前提表只有约 20 组，人工维护**。覆盖不了所有领域，遇到表外的前提组合会退化为"无法推演"。
4. **规则引擎的聚类较弱**。它能保证「至少产出 1 个争点」，但争点质量明显低于模型路径。少于 2 条立场不同的回答时，常常形不成争点。
5. **没有多语言能力**。赛题把「跨语言理解」列为方向之一，我们没做。
6. **湾区元素只有一集示例数据**。第四集是跨境卖家「平台还是独立站」的话题，把湾区产业土壤当案例用，但我们没有真实湾区用户数据，也没有做任何地域调研——它证明的是「同一套机制能读另一种行业」，不是一个湾区研究。
7. **公网演示版走规则引擎**。静态站点没有后端，无法调用模型；评委若填自己的模型 Key，可体验完整 AI 路径。
