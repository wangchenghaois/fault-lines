# 歧见 · Fault Lines

> 不告诉你答案，告诉你答案为什么分成两半。

一个跑在你自己电脑上的工具：把知乎问题下面那一大堆回答，拆成一张**观点断层剖面图**——哪些分歧是事实（能查）、哪些是价值（只能投票）、哪些是预测（只能等）。然后，你站到任一边，它推演出你在**别的争点上逻辑上必须站哪边**，以及这么站要付的代价。

赛道：知乎 S3 湾区共创季 · 01 社区 × 知识发现。

![歧见：一场争论的断层剖面](docs/img/screenshot.png)

<sub>四个内置示例之一「跨境电商还要不要自建独立站」的实机截图：蓝色=事实断层、橙色=价值断层、紫色=预测断层、绿色=共识基线。</sub>


---

## 它解决的问题

一个高赞问题下有几百上千条回答。你读三个小时，得到的是"很多人意见不同"这个结论——但你说不清**他们到底在什么层面上不同**。

真正的困难不是"信息不足"，是**争论的类型被混在一起**：

- 有人说「不结婚主要是因为买不起房」——这是**事实**判断，可以查数据；
- 有人说「不结婚是因为年轻人不再把婚姻当成必选项」——这也是**事实**判断，也可以查；
- 有人说「不该催婚，这是个人自由」——这是**价值**判断，**永远查不出结果**；
- 有人说「如果房价降一半，结婚率就会回升」——这是**预测**，只能等时间给答案。

绝大多数网络争吵的痛苦，来自**把价值断层当成事实断层来吵**：双方各自搬证据，谁也说服不了谁，因为那根本不是证据能解决的问题。

歧见做的就是给争论**分层**，让"我们到底在吵什么"这件事本身变得可见。

---

## 五层机制

| 层 | 做什么 | 产出 |
|---|---|---|
| 1 论点萃取 | 把每条回答拆成独立主张，标注类型（事实/价值/预测/因果/定义）、方向、所依赖的前提标签 | `claim` 列表 |
| 2 争点归并 | 把指向同一矛盾的主张聚成一个争点，分到两侧 | 2–4 个 `issue` |
| 3 **断层判定** | 判定这个争点的分歧性质：能被证据解决？只能投票？只能等？ | `fault: fact / value / prediction` |
| 4 共识基线 | 找出双方其实都同意的部分 | 共识条目 |
| 5 **信念推演** | 你选一边 → 用前提标签的重叠/互斥，推出你在其他争点上的位置 + 与你原有直觉冲突的论据（代价） | 投影 + 代价 |

附加两个区域：**孤证区**（只有一个人这么说的反例，最容易被当成普遍规律）和**沉默的多数**（只描述经历、不参与论断的回答——他们常常才是大多数）。

### 信念推演为什么不是"猜"

每个主张背后都有**前提标签**（经济决定论、理性人假设、制度决定论、观念独立变量……），代码里有一张互斥表：选了「经济决定论」，就不能同时持有「观念独立变量」。于是你选了一边之后，其他争点上哪些立场与你的前提相容、哪些冲突，是可以推导的，不是随机的。

这才是有价值的部分：**它不只是复述你的立场，它告诉你为了守住这个立场，你必须接受哪些你原本不接受的东西。**

## 跑起来

三种方式，按需要选：

**1. 直接双击（最简单，完全离线）**

```
dist/歧见.html
```

单文件，CSS 和 JS 全部内联，不联网、不需要服务器、不需要 API Key。四个内置数据集可以直接点（AI 编程工具 / 读博值不值 / 婚育 / 跨境电商独立站）。

**2. 本地服务器（开发用）**

```bash
node server.mjs 4188     # 或 npm start
# 打开 http://127.0.0.1:4188/
```

零依赖，只需要 Node。Windows 上也可以直接双击 **`start.bat`**：它会检查 Node 和本机模型服务、起服务器、自动打开浏览器。

> `start.bat` 内部只用英文提示。这是有意的——UTF-8 的 .bat 在部分 Windows 语言环境下会把中文和 `if` 语句一起解析坏（实测 `if "%X%"=="1"` 会被拆断成非法命令）。中文说明放在这里和网页里，不跟 cmd 的编码较劲。

**3. 用自己的数据**

点右上角「导入」：

1. 「问题标题（可空）」填这个问题本身。不填也行——如果第一行短、且以问号结尾，它会被当成标题，并从回答里剔除。
2. 下面粘回答正文，**回答之间用空行（连续两次回车）或 `---` 分隔**，带 `1. 2. 3.` 编号也可以，编号会被剥掉。
3. 「用本地模型分析」默认勾选；关掉它走规则引擎，0.2 秒出结果，质量明显更粗（只按关键词重合度聚类）。

需要 Ollama 在跑（`ollama serve`，模型名默认 `qwen3.5:4b`，可在设置里改成任意 OpenAI 兼容端点；注意多数厂商不允许浏览器直连，这种场景要用服务端代理，见 `docs/11-部署方案.md`）。分析大约 70–80 秒，界面会显示分阶段进度条；模型不在线时会明确告诉你「模型端点无响应」，并自动降级到规则引擎出结果，不会白等。

支持深链，方便录屏和演示：

```
?ds=marriage&issue=i3&side=A
```

## 推理引擎：默认全本地

- 默认后端是 **Ollama**（`http://127.0.0.1:11434/v1`，模型 `qwen3.5:4b`）。
- 右上角的引擎指示灯会探活；没装 Ollama 也能用——自动降级到**规则引擎**（信号词分类 + 词重合度聚类），功能不缺失，精度下降。
- 任何 OpenAI 兼容的 endpoint 都能在「设置」里填（含 API Key），数据不出本机是默认行为，不是限制。

### 一个必须知道的坑：reasoning 模型的空返回

`qwen3.5:4b` 是 thinking 模型。**不关思考时，它会把整个 token 预算烧在思维链上，`content` 返回空字符串**——实测单次 32 秒、1401 字推理、0 字正文。如果不处理，表现就是"每次调用都卡到超时，然后悄悄降级到规则引擎"，看起来能用，其实 AI 一次都没跑通。

`src/engine/llm.js` 里的处理：

- 请求带 `reasoning_effort: 'none'`（OpenAI 兼容口），同一任务从 32 秒/空返回变成 **3.5 秒/干净 JSON**；
- 若端点返回 400/422（不认这个字段），自动退一步重试；
- 正文为空但 `reasoning_content` 有内容时**立刻报错**并说明原因，不静默等到超时。

原生 `/api/chat` 的 `think:false` 也能达到同样效果（实测 3.6 秒）。诊断脚本留在 `scripts/llmprobe.mjs` 和 `scripts/llmthink.mjs`，换模型时可以重跑一遍。

### 真实耗时（本机 4.2B / Q4_K_M / GTX 1650 4GB）

| 场景 | 耗时 |
|---|---|
| 探活 | 0.1s |
| 单条回答抽主张（热） | 2.9–9.4s |
| 3 条回答全流程（抽取 + 归并 + 共识） | **70–82s** |
| 4 条回答全流程 | **约 130s** |
| 冷启动（模型首次载入显存） | 最多 90s，**一次性** |
| 后端不通（端口没开） | 43ms 即报错并降级 |
| 同样的文本走规则引擎 | < 0.2s |

两个工程细节值得说明，因为它们都是实测撞出来的：

1. **必须先预热**。本地模型第一次调用要把权重读进显存，实测可以吃满 90 秒超时预算，导致第一条回答直接 abort、整轮降级。现在 `analyze()` 在抽取前先跑一次极短的预热调用（`输出 {"ok":true}`，预热自身给 180 秒预算），冷启动的代价只付一次，后续每条回答 3–10 秒。
2. **后端挂了要说人话**。以前 Ollama 进程死掉时，界面报「主张数量不足，无法构建争点」——用户会以为自己的文字有问题。现在预热失败直接抛「模型端点无响应（fetch failed）：请确认 Ollama 已启动、模型名正确」。

所以界面在导入分析时会显示阶段进度条（第 N/M 条回答、归并、共识）。**内置的四个数据集是预先分析好的，切数据集是瞬时的**——只有"分析你自己的文字"才需要等。

这一点对这类产品很重要：**你在看的是别人的真实表达，把它上传到某个服务器去做分析，本身就是一种冒犯。**

## 工程规范

这一节是给看代码的人准备的——「能跑」和「工程上站得住」是两件事。

**没有构建框架、没有运行时依赖。** 前端是原生 ES 模块 + 一个 200 行的自制打包器（`tools/bundle.mjs`），产出可以双击打开的单文件 HTML。唯一的开发依赖是 jsdom（只给测试用）。`npm i` 只为一个包，`git clone` 下来不装也能 `node tools/bundle.mjs` 出产物。

**测试分了六层，每层管一种失败方式。** 这不是为了数字好看，而是每一层都真的抓到过 bug：

| 层 | 条数 | 管什么 | 抓到过的真实问题 |
|---|---|---|---|
| `selftest` | 385 | 纯逻辑：数据结构、全数据集×全争点双向推演、JSON 抢救、文本切分 | 规则引擎一个争点都产不出；切分只认三个换行 |
| `providertest` | 71 | 模型商与知乎客户端的请求形状、错误码映射、字段归一 | `Data.Items` 嵌套取不出来（返回空数组） |
| `assets` | 19 | 资源引用是否都能解析 | `providers.js` 写好了但从来没被 import（死代码） |
| `domtest` | 50 | jsdom 里跑完整交互：切数据集、点争点、站边、导入弹窗、空结果 | 进度条倒退；0 争点时白屏 |
| `cleanroom` | 12 | `file://` + 断网 + 无模型的最坏环境 | `file://` 下 localStorage 抛异常，整个 init 挂掉 |
| `servertest` | 14 | 服务端代理：鉴权头、额度限流、reasoning_effort 注入、SSRF 防线 | —（新增代码时同步写的） |

另有一条**部署模式端到端**（`scripts/demotest.mjs`，8 条）：把本机 Ollama 当成云厂商端点，jsdom 以 http 打开页面，验证「评委不装任何东西、不填 Key」这条唯一会被评委走的路径。它不进 `npm test`，因为要 80 秒且依赖本机模型。

**每个功能都要有两种输入。** 模型可用时走模型，模型不可用时降级到规则引擎，且界面必须**说清楚现在用的是哪个**——降级不能伪装成正常。

**没有验证能力就说没有。** `docs/04` 里明确写了哪些结论是机器测的、哪些需要人眼；`docs/08` 明确写了知乎接口验证到哪一步、参数名没有实测。工程文档里最贵的不是漂亮话，是让人能判断「这句能信到什么程度」。

**干净克隆能复现。** 这个仓库不依赖构建框架、不提交构建产物：clone 下来只有 55 个源文件（`.git` 568 KB），不装依赖就能跑出单文件，装了依赖就能跑全部测试。

```
$ git clone <repo> /tmp/q && cd /tmp/q
$ node tools/bundle.mjs        # 无 node_modules 也能出产物（dist/歧见.html 131 KB）
$ node tools/selftest.mjs      # 385 条：引擎与数据
$ node tools/assets.mjs        # 19 条：引用完整性
$ node tools/providertest.mjs  # 71 条：知乎/模型商客户端
$ node tools/servertest.mjs    # 14 条：服务端代理
$ npm i                        # 只装一个包：jsdom
$ npm test                     # 385 + 71 + 19 + 50 + 12 + 14 全绿
```

**提交信息按「做了什么 + 为什么」写**，不写「update」；每个提交是一件可以被单独看懂的事：

```

补齐六层测试与打包器：551 条断言覆盖逻辑/接口/资源/渲染/离线/服务端
```

### 部署到公网

`server.mjs` 是一个可部署的 Node 服务（零依赖），承担三件事：静态文件、知乎代理、模型代理。

```bash
PORT=8080 LLM_BASE_URL=https://api.deepseek.com/v1 LLM_API_KEY=sk-xxx LLM_MODEL=deepseek-chat node server.mjs
```

配了 `LLM_BASE_URL` + `LLM_API_KEY` 之后，`/api/health` 会告诉前端「服务端模型可用」，前端自动把「AI 分析」指向它——**评委不需要装 Ollama，也不需要填自己的 Key**。没配就诚实地显示「将使用规则引擎」。

三条部署路线（知乎 AiWorks / CloudBase / 云主机）、环境变量表、部署后自查命令，都在 `docs/11-部署方案.md`。

## 数据说明（重要，别把它当知乎原文）

内置的四个数据集是**依据公开讨论重构的示例**，用来演示机制，不是知乎原文引用，也不是真实用户的原话。每集 5–6 条回答、7–11 条主张、4 个争点：婚姻、读博、AI 取代程序员，第四集是粤港澳大湾区的跨境卖家话题（平台 vs 独立站）——它属于「赛道 01 的知识发现」用湾区产业土壤做的例子，不是硬凑的地名。

真实使用方式是导入你自己关心的那个问题的回答——那时数据是你自己的，留在你自己的机器上。

为什么不做抓取：知乎对程序化访问有反爬限制，硬爬既不体面也不稳。**这个产品的定位是"你已经有了一堆文字，我帮你读懂它"，不是"我替你去偷一堆文字"。**

## 接知乎开放平台（可选）

如果你有知乎开放平台的 `access_secret`，可以让歧见直接拉真实内容，链路是：

**话题关键词 → 推荐的知乎问题 → 该问题下的真实回答 → 断层图**

在导入弹窗里展开「从知乎拉取」，填 Secret，输入话题（如「考研」「跨境电商」），点「找问题」，选一个问题就把回答灌进文本框。

用的是这几个端点（按官方文档实现）：

| 端点 | 用途 |
|---|---|
| `GET /api/v1/user/question_recommendations` | 话题 → 问题列表 |
| `GET /api/v1/content/question_answers` | 问题 → 回答摘要（分页按 `Paging.IsEnd`） |
| `GET /api/v1/content/zhihu_search` | 站内搜索 |
| `GET /api/v1/content/hot_list` | 热榜 |
| `GET /api/v1/quota` | 剩余额度 |
| `GET /api/v1/user/creator_account_stats` | 本人创作数据 |

三条限制必须知道：

1. **只有本机跑才有代理**。浏览器不能直连知乎（没有 CORS），所以 `node server.mjs 4188` 起了一个转发路由 `/api/zhihu`，Secret 走请求头不走 URL，且只允许转发以 `/` 开头的路径。公网静态版没有这个代理——这是有意的，静态站点不该持有你的 Secret。
2. **我们没用真凭证跑通过**。用假 Secret 打过 6 个端点，全部返回 `20001 鉴权失败`，而写错路径返回 `404 page not found`，说明路径与鉴权头格式对；但参数名大小写验不了（知乎先校验鉴权）。详见 `docs/08-知乎接口实测.md`。
3. **热榜和搜索拿不到赞数以外的统计**。`hot_list` 只有标题/链接/摘要，所以早期设想的「回答密度」「需求供给比」这类指标是算不出来的，已经删掉，只保留接口真拿得到的数（赞数中位数、前 3 赞占比、零评论占比）。

没有 Secret 也完全能用：粘贴回答，或直接用内置示例。

## 已知限制

- 内置数据集只有四个，规模小，是演示用的。
- 规则兜底引擎按「是不是同一话题」聚类，**不判断立场是否真对立**：几条其实同一个立场的回答，它也会硬拆成两边，做出一个伪争点。LLM 路径没有这个问题。公网静态版（没有后端模型）走的就是规则引擎，这一条对评委看到的效果有直接影响。
- 信念推演的互斥表是人工维护的（约 20 组），覆盖面有限；遇到表里没有的标签，只会按字面重叠判断。
- 没有做多语言（赛道里"跨语言"那条方向没有做）。
- 没有账号、没有云端、没有协作——这是刻意的。
- 本机 4B 模型在这台 GTX 1650（4GB 显存）上，3 条回答的分析约 70 秒，4 条约 110–130 秒；等待期间有进度条，但没有流式输出。
- 少于 2 条立场不同的回答时，常常形不成争点——界面上会给出提示，而不是硬凑一个对抗出来。

## 一句话

争论的价值不在谁赢，在于**看清这条缝在哪里、它是哪种缝**。

歧见不投票，不给结论，不站队。它只是把那道缝剖开给你看。
